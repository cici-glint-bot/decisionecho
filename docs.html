DecisionEcho — Documentation

Last updated: 19 November 2026

DecisionEcho is a team decision-memory layer for Jira and Confluence, built on Atlassian Forge with a Rovo agent. It captures the decisions your team makes — the conclusion, the rationale, the alternatives that were rejected and why, the owner, and the source — into a structured store, so that people and AI agents can check why something was decided before they start work, instead of rebuilding what was already rejected.

Getting started

  1. Install DecisionEcho on your Jira / Confluence Cloud site from the Atlassian Marketplace.
  2. Open Rovo Chat and select the DecisionEcho agent.
  3. Ask it to record a decision, or ask for a decision brief on any issue (see below).

Recording a decision

Tell the agent about a decision in plain language, for example: "Record a decision: Payments stay on the legacy gateway until Q3, because the contract runs until then. We rejected migrating to the new API now — it lacks refund webhooks. Owner: payments team. Linked issue: DEMO-1."

The agent shows a confirmation before anything is written. Each record stores: title, conclusion, rationale, rejected alternatives with reasons, tags, linked issue keys, the author's display name, and a source URL. Recording is idempotent — repeating the same request does not create duplicates.

Decision briefs (before you start work)

Ask the agent: "Give me the decision brief for issue DEMO-3." The brief returns:

  • Relevant decisions — active decisions that match the issue, each with the keywords that matched, its rationale, and a source link;
  • Red lines — alternatives that were previously rejected, with the reason they were rejected;
  • Superseded warnings — decisions that were later replaced, so you don't act on stale guidance;
  • Teamwork Graph context — recent issue comments and linked Atlassian Goals are read (as you, within your permissions) and used to improve matching.

For the richest brief, open the agent from the issue page so the issue context is attached.

Jira issue panel

Every Jira issue shows a DecisionEcho panel listing the decisions that govern that issue, with their status and source links — the same information as the agent brief, without asking.

Use from your own tools (MCP)

DecisionEcho exposes its record / search / brief tools through the Atlassian MCP endpoint for the app, so other MCP-compatible agents can query the team's decision memory before acting. Access requires OAuth authorization as a user of a site where the app is installed.

Data and privacy

Decision records are stored in Atlassian Forge app storage on your site. The app sends no data to the developer or any third-party server. See the Privacy Policy for details.
